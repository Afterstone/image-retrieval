# Model migration preflight

Verified 2026-10-24. Scope: documentation, pinned checkpoint metadata, and installed library source only. **No weights were loaded, no network inference was performed, and no real-model or CPU/MPS hardware certification is claimed.** The successful `uv sync` with Python 3.14.9, Transformers 5.20.2, and Sentence Transformers 6.2.0 is a supplied main-agent/user observation, not a command rerun for this research. The main agent also supplied an `inspect` verification of the Transformers feature-return contract; installed source independently corroborates it below. [E1][L4]

## Findings that affect adapter correctness

### EmbeddingGemma 2

- Pin `google/embeddinggemma-2` to **`914f7f89142e33e77833254d9c9b90c3cef7303b`** for the model and its associated processor/configuration. The checkpoint's Sentence Transformers configuration requires **Sentence Transformers >=6.1.0**, explicitly because older versions mishandle multimodal dictionary ordering and multiple media/text items in one embedding. Its recorded build versions (ST 6.1.0, Transformers 5.18.0.dev0) are provenance, not an exact runtime requirement. [G1][G2][L5]
- The native shared text/image output is **768-dimensional**, not the 512-dimensional backbone width. The card specifies a 512→768 projection; the saved pipeline is Transformer → Pooling → Normalize, with pooling configuration `embedding_dimension=768`, `pooling_mode="mean"`, and `include_prompt=true`. Use that saved Sentence Transformers pipeline rather than substituting raw backbone states, CLS pooling, or prompt-excluding pooling. Retain native dimensions for this migration; do not silently enable Matryoshka truncation. [G1][G3][G4][G5]
- **Image inputs can be decoded Pillow objects.** Google's multimodal guide documents `{"image": <source>}` with a path, URL, or `PIL.Image` object. Prefer a batch containing one `{"image": pil_image}` dictionary per input image; a single dictionary whose `image` value is a list represents a combined multimodal sample, not a batch of independent vectors. Installed ST 6.2.0 also recognizes bare Pillow images, and its input types permit Pillow objects inside image dictionaries. Do not send paths/URLs when the application already owns decoding. [G6][L1][L2]
- **Use float32 for the migration baseline; reject float16 inference/autocast.** Google explicitly states that EmbeddingGemma 2's activation range exceeds float16 and can produce NaNs or silently degraded embeddings. Google allows bfloat16 on supported hardware, but that is not evidence that this application's Mac configuration is certified. The card demonstrates explicit inference dtype through `model_kwargs={"torch_dtype": dtype}`; merely converting final embeddings to float32 cannot undo fp16 inference errors. [G1][G5]
- **Omit the unused audio encoder by setting `config_kwargs={"audio_config": None}`**, while retaining vision. This is the documented SentenceTransformer text-and-image configuration (approximately 440M parameters versus 740M full multimodal). Do not set `vision_config=None` for image retrieval, and do not confuse explicit `audio_config=None` with omitting the override, which retains the default audio encoder. This configuration is documented, not load-tested here. [G1][G5][G6]

### Text-to-image prompting: verified behavior versus unresolved intent

**Do not claim that `SearchQuery` is conclusively verified as the text-to-image recipe.** The primary sources distinguish the following evidence:

| Evidence | What it establishes |
| --- | --- |
| Pinned prompt configuration | `SearchQuery` and `query` both expand to exactly `task: search result | query: ` (including the trailing space); `Document` expands to `title: none | text: `. `default_prompt_name` is **null**. [G2] |
| Pinned README / Google v2 card | Generic asymmetric retrieval guidance recommends a query prefix; the table labels `SearchQuery` specifically **web/document search**. The quick start pairs prefixed text queries with prefixed text documents. Prefixes apply only to text; images are passed without prefixes. This is not an explicit text-to-image instruction. [G1][G5] |
| Google's multimodal guide source, “Working with Images” | Encodes an image with `model.encode({"image": img_url})`, then candidates including `"San Francisco"` using `model.encode(candidates)` with **no prompt argument**. The accompanying prose calls `"San Francisco"` a text query. This is concrete unprefixed image/text similarity evidence, not an explicit comparison of retrieval prompt quality. [G6] |
| Installed ST 6.2.0 | `_resolve_prompt` only selects a named/default prompt when configured; with the pinned null default, ordinary `encode` does not automatically apply `SearchQuery`. Conversely, `encode_query` selects the configured `query` prompt when no prompt is supplied. These calls are therefore **not interchangeable** for this checkpoint. [G2][L3] |

**Recommendation (application decision, not a vendor guarantee):** use explicitly unprefixed text encoding as the initial text-to-image baseline to reproduce the concrete multimodal example, e.g. the equivalent of `encode(text_batch, prompt="")`; encode image queries and corpus images without task prefixes. Do not apply `Document` to images or introduce a `Clustering` prompt merely because stored image vectors are later clustered. If choosing `SearchQuery` instead, label that choice as an extrapolation from generic retrieval guidance, record the exact prefix in recipe identity, and test it separately. The reviewed sources do **not** resolve whether prefixed or unprefixed text gives better text-to-image retrieval on this corpus. No comparative inference was performed. [G1][G2][G5][G6][L3]

**Additional routing precaution:** ST detects media-looking strings as media paths/URLs when the model supports that modality. To guarantee arbitrary user query strings remain text, consider explicit `{"text": query}` samples and verify their prompt behavior with offline doubles; explicit image dictionaries keep modality intent equally clear. This is a recommendation based on the installed modality detector, not a real-model test. [L1][L2]

### SigLIP2

- Pin `google/siglip2-so400m-patch14-384` to **`e8e487298228002f3d8a82e0cd5c8ea9c567f57f`** for both `AutoModel` and `AutoProcessor`. Despite the SigLIP2 repository name, this checkpoint declares `model_type="siglip"`, with `siglip_text_model` and `siglip_vision_model` components; do not select an architecture solely by the repository's name. The card explicitly lists image-text retrieval as an intended use. [S1][S2]
- Native projected/pooled vectors are **1152-dimensional** on both sides: text hidden/projection sizes are 1152 and vision hidden size is 1152. Vision configuration specifies image size 384 and patch size 14. Installed code projects the final text position through the text head and uses the learned multihead-attention pooling head for vision; use these outputs, not a hand-written mean over patch tokens. [S2][L4]
- **Transformers 5.20.2 `get_text_features` / `get_image_features` return a ModelOutput (`BaseModelOutputWithPooling`), not the bare embedding tensor in the older card example.** Request dictionary output (`return_dict=True`) and read **`.pooler_output`**, then validate and normalize that tensor. This agrees with the main agent's supplied `inspect` verification and the installed method bodies. Tuple mode remains possible, so do not rely on tuple indexing or call `.norm()` on the entire return object. [S1][L4][E1]
- The feature helpers return their tower outputs **before normalization**. `SiglipModel.forward` explicitly L2-normalizes each `.pooler_output` before dot products, then applies learned logit scale and bias. For this application's cosine ranking, normalize features independently; do not persist classification logits or sigmoid probabilities as embeddings. [L4]
- Installed SigLIP documentation requires text **`padding="max_length"`** because that matches training; its implementation pools the last position, which can be padding. Use the pinned tokenizer/processor for special tokens, length limits, and preprocessing rather than copying OpenCLIP settings. The source examples accept Pillow images through `processor(images=..., return_tensors="pt")`. Float32 is the migration's conservative policy for this adapter, not a discovered SigLIP2 prohibition on other dtypes. [L4][S1][S2]
- **Prompt semantics remain bounded:** no reviewed pinned SigLIP2 source establishes a mandatory `SearchQuery`, `Document`, or `a photo of ...` wrapper for arbitrary text-to-image queries. “A photo of” appears in installed examples, not as proof of a universal retrieval requirement. Keep any application text template explicit and recipe-versioned; do not import Gemma task prefixes into SigLIP2. [S1][L4]

## Dependency and verification status

- PyPI release metadata for **Transformers 5.20.2** declares Python `>=3.10.0` and includes Python 3.14 classifiers. **Sentence Transformers 6.2.0** declares Python `>=3.10`, includes Python 3.14, and requires `transformers>=5.0.0,<6.0.0` and `torch>=2.2`. Therefore the selected Transformers release satisfies ST's declared range and ST 6.2.0 satisfies the checkpoint's >=6.1.0 requirement. This is metadata compatibility, not proof that every transitive dependency or device path works. [P1][P2][G2]
- ST's image extra requests `transformers[vision]`; Transformers 5.20.2's vision extra includes torchvision and Pillow `>=10.0.1,<=15.0`. An installation resolving successfully is not evidence that either checkpoint initializes or that optional image kernels execute on Python 3.14/MPS. [P1][P2][E1]
- **Still unverified:** actual pinned weight loading, model/processor execution together, finiteness and unit norms under real inference, CPU/MPS equivalence, memory requirements, retrieval quality, and fp32 hardware execution. The text-to-image prefix-quality ambiguity above remains open. Offline adapter tests should cover ModelOutput extraction, exact prompt/no-prompt selection, Pillow batch boundaries, dtype propagation, dimensions, and invalid-output rejection; these are recommendations, not completed tests. [E1][G2][G6][L1][L3][L4]
